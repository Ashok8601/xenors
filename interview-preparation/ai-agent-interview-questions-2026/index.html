Core interview questions and concise model answers

1. What makes a system an AI agent?

An agent receives a goal, reasons about the next step, can call tools or act on an environment, observes the result and continues until a stop condition is met. The important distinction is the action-and-feedback loop.

2. What is tool calling?

Tool calling lets the model request a typed external operation such as search, database access or code execution. Validate arguments, authorise each tool, time out safely and treat tool output as untrusted data.

3. What is an agent loop?

A basic loop is plan or decide, act, observe and evaluate. Production loops also need budgets, retries, idempotency, timeouts, traceability and explicit termination rules.

4. How should an agent use memory?

Separate short-term conversation state from durable memory. Store only useful facts with provenance and expiry rules; retrieval quality and privacy controls matter more than accumulating everything.

5. Single agent or multi-agent?

Prefer one agent when the task can be solved with a clear toolset. Add multiple agents only when specialised roles or parallelism create measurable benefit because coordination adds latency and failure modes.

6. How do you prevent dangerous tool use?

Use least-privilege credentials, allowlists, scoped tools, human confirmation for irreversible actions, sandboxing and policy checks before execution.

7. How do you evaluate agents?

Measure end-to-end task success, tool accuracy, number of steps, cost, latency, recovery from failure and safety violations on realistic scenarios.

8. How do you debug an agent that loops forever?

Inspect traces for repeated state, ambiguous success criteria, tool errors and prompts that fail to update the plan. Add step budgets and explicit stop conditions.
