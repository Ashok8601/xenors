Core interview questions and concise model answers

1. What is model versioning?

Track the model artifact together with code, configuration, feature definitions and training data references so a prediction can be reproduced.

2. Batch vs online inference?

Batch inference trades freshness for throughput and simplicity; online inference serves requests with strict latency and availability targets.

3. What is a feature store?

A feature store standardises feature definitions and serves consistent values for training and inference, helping prevent training-serving skew.

4. How do you monitor ML systems?

Monitor service health, feature distributions, prediction distributions, data quality and delayed outcome metrics. Alerts need actionable thresholds, not just dashboards.

5. What is canary deployment?

Send a small share of traffic to the new model, compare technical and business metrics, then expand or roll back based on predefined criteria.

6. How do CI/CD and CT differ?

CI/CD automates code testing and deployment; continuous training adds controlled model retraining when new data or drift criteria justify it.

7. How do you make pipelines reproducible?

Pin environments, version data references, make transformations deterministic where possible, store metadata and avoid hidden notebook state.

8. What causes training-serving skew?

Different preprocessing code, stale features, schema changes or time semantics can make production inputs differ from training assumptions.

How interviewers go deeper

Expect follow-ups such as “why this metric?”, “what failed first?”, “how did you know the improvement was real?”, and “what would change at ten times the traffic?”. Revision checklist

  • Explain each concept in under 90 seconds.
  • Give one example from a real or portfolio project.
  • Name one failure mode and one measurement.
  • State when you would choose a simpler alternative.
  • Separate what you implemented personally from team work.
