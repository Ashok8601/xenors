## Items intentionally NOT VERIFIED / owner action required

1. **Live HTTP 404 behavior:** the project includes `404.html`, but the exact HTTP status and custom-404 behavior must be verified after deployment on the chosen host.
2. **OneSignal end-to-end push:** code and service worker are present, but `oneSignalAppId` is intentionally blank because no owner account/App ID was supplied.
3. **Email double opt-in:** the form is wired to a configurable hosted action, but `emailFormAction` is blank until the owner creates/chooses the newsletter provider form.
4. **RSS-to-push automation:** current OneSignal free-plan pricing confirms web push and API send access, but a direct current free RSS-to-push feature was not verified from official documentation. Use the manual checklist in `DEPLOY_README.md` unless you configure an external automation.
5. **RSS-to-email automation:** Buttondown currently lists RSS-to-email as a +$9/month add-on; MailerLite documents RSS campaigns as paid. Free plans can still be used for manual campaigns within their limits.
6. **Visual uniqueness:** exact file-hash duplicate checking found no repeated high-priority hero files among normal content pages, but perceptual/visual uniqueness of hundreds of generated images is NOT VERIFIED by this static audit.
7. **One-CSS-file target:** common site CSS is merged, but existing page-specific CSS was preserved where removing it risked layout breakage. Therefore “exactly one CSS file on every legacy page” is NOT VERIFIED/NOT fully achieved.
