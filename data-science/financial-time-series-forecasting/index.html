Project: Stock Price Forecasting with LSTM and Prophet

Forecasting prices is a good way to practise time series modelling, and an honest way to learn how hard markets are to predict. Treat this as a modelling exercise, not trading advice.

Quick answer: Download prices with yfinance, forecast with Prophet and an LSTM, then compare both against a naive last-value baseline using walk-forward validation. Markets are noisy, so a model that cannot beat the naive baseline has no predictive value.

Disclaimer and setup

This project is educational. Forecasts of prices are uncertain and are not financial advice. Past performance does not predict future returns.

Download daily prices
# pip install yfinance prophet scikit-learn torch pandas
import yfinance as yf, pandas as pd

raw = yf.download("RELIANCE.NS", start="2018-01-01", progress=False, auto_adjust=True)
close = raw["Close"].squeeze().dropna()
df = close.reset_index()
df.columns = ["ds", "y"]
print(df.tail())

Baseline first

On daily prices, 'tomorrow equals today' is surprisingly hard to beat. Any model must clear this bar.

Naive last-value forecast
import numpy as np
split = int(len(df) * 0.85)
train, test = df.iloc[:split], df.iloc[split:]
naive = test["y"].shift(1).fillna(train["y"].iloc[-1])
mae = lambda a, b: float(np.mean(np.abs(a - b)))
print("naive MAE:", round(mae(test["y"], naive), 2))

Forecast with Prophet

Prophet fits trend and seasonality and gives uncertainty intervals. It suits business time series better than efficient financial prices, which makes it a useful comparison.

Prophet fit and evaluation
from prophet import Prophet

m = Prophet(daily_seasonality=False, weekly_seasonality=True, yearly_seasonality=True)
m.fit(train)
future = m.make_future_dataframe(periods=len(test), freq="B")
fc = m.predict(future)
pred = fc.set_index("ds").loc[test["ds"], "yhat"].values
print("Prophet MAE:", round(mae(test["y"].values, pred), 2))

Forecast with an LSTM

Predict the next day's return from the previous 30 returns. Modelling returns instead of raw prices makes the series closer to stationary.

LSTM on normalised log returns
import torch, torch.nn as nn
ret = np.log(df["y"]).diff().dropna().values.astype("float32")
mu, sd = ret[:split].mean(), ret[:split].std()
r = (ret - mu) / sd
W = 30
X = np.stack([r[i:i+W] for i in range(len(r) - W)])[..., None]
y = r[W:]
Xt, yt = torch.tensor(X[:split-W]), torch.tensor(y[:split-W])
Xv, yv = torch.tensor(X[split-W:]), torch.tensor(y[split-W:])

class Net(nn.Module):
    def __init__(s):
        super().__init__(); s.l = nn.LSTM(1, 32, batch_first=True); s.o = nn.Linear(32, 1)
    def forward(s, x): return s.o(s.l(x)[0][:, -1]).squeeze(-1)

net = Net(); opt = torch.optim.Adam(net.parameters(), 1e-3)
for ep in range(10):
    for i in range(0, len(Xt), 64):
        opt.zero_grad()
        loss = nn.functional.mse_loss(net(Xt[i:i+64]), yt[i:i+64]); loss.backward(); opt.step()
with torch.no_grad():
    print("LSTM val MSE:", float(nn.functional.mse_loss(net(Xv), yv)),
          "| zero-return baseline:", float((yv ** 2).mean()))

Interpret results honestly

If the LSTM error is not lower than the zero-return baseline on unseen data, it has learned nothing useful. Use walk-forward validation, include transaction costs before drawing conclusions about strategies, and be cautious about backtests that look too good, since overfitting is the usual cause.

Frequently asked questions

Can LSTM predict stock prices accurately?

Not reliably. Prices are noisy and efficient markets leave little predictable signal, so always compare with a naive baseline.

Prophet or LSTM?

Prophet is quick and interpretable for trend and seasonality. LSTMs can model more complex patterns but need more data and careful validation.

Is this financial advice?

No. It is an educational modelling exercise only.
