How to add a canonical tag in HTML

Quick answer: Put a single <link rel="canonical"> element in the page's HTML <head>, using the absolute HTTPS URL you want search engines to treat as the preferred version. Put the same self-referencing canonical on the preferred page. This is a strong preference signal, not a redirect or a guarantee that Google will select that URL.

<link rel="canonical" href="https://example.com/guides/industrial-ai-cameras/">

Use this when multiple URLs show the same or substantially similar primary content—for example, tracking-parameter variants of a guide. If two pages answer different questions, keep distinct canonical URLs rather than collapsing them together. For a broader page structure checklist, see the HTML SEO basics tutorial.

Canonical tag HTML example: preferred URL and duplicate

Imagine a manufacturer publishes an industrial AI camera guide at the clean URL https://example.com/guides/industrial-ai-cameras/. Its marketing email adds ?utm_source=email, creating another URL that displays the same guide.

1. The preferred page (self-canonical)

This is the complete small HTML document. The canonical belongs inside <head>, not in the visible page body.

<!doctype html>
<html lang="en">
<head>
  <meta charset="utf-8">
  <title>Industrial AI Camera Guide | Example</title>
  <meta name="description" content="A practical guide to industrial AI cameras.">
  <link rel="canonical" href="https://example.com/guides/industrial-ai-cameras/">
</head>
<body>
  <main>
    <h1>Industrial AI Camera Guide</h1>
    <p>Camera choices, latency checks and commissioning tips.</p>
  </main>
</body>
</html>

2. The near-duplicate parameter URL

If the parameterized URL returns the same HTML, it can carry the same canonical destination. The tag does not remove the query string from the visitor's address bar.

<!-- Also place this in the head of the near-duplicate URL:
     https://example.com/guides/industrial-ai-cameras/?utm_source=email -->
<link rel="canonical" href="https://example.com/guides/industrial-ai-cameras/">

Expected outcome: Both URLs declare the clean guide URL as preferred. Google may still evaluate other signals, such as redirects, sitemap URLs, internal links and actual content similarity, before choosing the canonical.

Canonical vs redirect vs noindex vs robots.txt

MechanismWhat it doesUse it when
301/308 redirectMoves visitors and crawlers to another URL; strong canonical signalThe old URL should no longer be visited separately
HTML rel=canonicalSuggests a preferred URL while keeping both pages accessibleNear-duplicate variants legitimately remain online
noindexAsks search engines not to index the pageYou want that individual page omitted; not a substitute for canonicalization
robots.txt disallowRestricts crawling of a URL pathYou need crawl controls; not a way to select a canonical
XML sitemapLists URLs you consider important; weaker canonical hintYou want crawlers to discover preferred indexable pages

Google Search Central explicitly advises against using robots.txt or noindex as a method for choosing among duplicate pages. Use a canonical link, appropriate redirects and consistent internal links instead. See the official Google canonicalization guide.

Which URLs should point to the same canonical?

URL variationTypical decisionReason
?utm_source=newsletterCanonical to clean URL if content is identicalTracking does not create a new topic
HTTPS and HTTP variantsPrefer HTTPS; redirect HTTP if possiblePick one consistent, secure primary address
/guide vs /guide/Use one form consistently; redirect the other if feasibleCanonical and sitemap must agree on the final URL
Filtered catalog pageEvaluate each view's unique content and search demandSome filters are duplicates; others are useful landing pages
Part 1 and part 2 of a tutorialUsually keep separate self-canonicalsDifferent primary material should stay discoverable
Same article republished on another domainConsider a cross-domain canonical when contents genuinely matchPreference can point across domains, but may not be honored

Never canonicalize every page to the homepage. Likewise, a canonical pointing at a category page is not a shortcut for improving poor article quality. The destination should be the best representative of substantially equivalent content.

Cross-domain canonical example for a syndicated article

If a partner republishes essentially the same full guide on another domain and both parties want the original to be the preferred result, the syndicated page can declare the original URL:

<link rel="canonical" href="https://publisher.example.com/guides/industrial-ai-cameras/">

This is not an ownership proof and does not force Google to use the target. The publisher must agree to the arrangement, and pages with meaningfully different content should keep their own canonicals. Prefer linking to the original when syndication is not an exact or near-exact copy.

How to verify a canonical tag on the live page

First inspect the raw HTML response. In Chrome, use View Page Source and search for rel="canonical" inside the <head>. Developer Tools can show a JavaScript-modified DOM, which may differ from what the server initially sends.

Then run a reproducible status and canonical check. Save the following as check_canonical.py and run python check_canonical.py. It uses only the Python standard library, prints the final URL after redirects and fails if there is not exactly one canonical in the head matching that URL. Replace the sample Xenors URL with your own.

# check_canonical.py  (Python 3, standard library only)
from html.parser import HTMLParser
from urllib.request import Request, urlopen

class CanonicalLinks(HTMLParser):
    def __init__(self):
        super().__init__()
        self.in_head = False
        self.urls = []

    def handle_starttag(self, tag, pairs):
        attrs = dict(pairs)
        if tag == "head":
            self.in_head = True
        elif self.in_head and tag == "link":
            if "canonical" in (attrs.get("rel") or "").lower().split():
                self.urls.append(attrs.get("href", ""))

    def handle_endtag(self, tag):
        if tag == "head":
            self.in_head = False

url = "https://xenors.in/home/code-lab/html/html-canonical-tag/"
req = Request(url, headers={"User-Agent": "CanonicalAudit/1.0"})
with urlopen(req, timeout=15) as resp:
    status, final_url = resp.status, resp.geturl()
    html = resp.read().decode("utf-8", errors="replace")

parser = CanonicalLinks()
parser.feed(html)
print("HTTP status:", status)
print("Final URL:", final_url)
print("Canonical tags in head:", parser.urls)

assert status == 200, "Page is not HTTP 200"
assert len(parser.urls) == 1, "Expected one canonical element in head"
assert parser.urls[0] == final_url, "Canonical differs from final URL"

The equality assertion is appropriate for self-canonical pages. For intentionally canonicalized duplicate or syndicated pages, compare the declared canonical with the chosen target rather than the duplicate page's final URL. A successful HTML check cannot guarantee indexing or which Google-selected canonical appears in Search.

Check the Google-selected canonical

Open the Google Search Console URL Inspection tool. Compare the user-declared canonical and Google-selected canonical. If they disagree, inspect actual duplicate content, internal linking, redirects and sitemap signals—not just the HTML tag.

Seven canonical tag mistakes to avoid

  1. Relative URLs: Google supports them, but absolute HTTPS URLs avoid errors caused by staging hosts or base URL changes.
  2. Two conflicting canonicals: do not output one from your template and another from a plugin or JavaScript.
  3. Canonical outside the head: place the link element in valid HTML <head>.
  4. Canonicals to a 404 or redirecting URL: point to a stable, indexable final destination.
  5. Canonical plus noindex for the same content cluster: noindex removes a page from results; it is not a canonical hint.
  6. Distinct topics canonicalized together: the tag is for duplicate or near-duplicate main content, not merely pages sharing a layout.
  7. Contradictory sitemaps and links: publish the final preferred URL consistently instead of linking and listing alternate variants.

Canonical URL deployment checklist

  1. Pick one final HTTPS URL that returns HTTP 200.
  2. Check that its page contains exactly one self-referencing canonical link in <head>.
  3. Confirm that duplicate variants point to the same destination, or permanently redirect if the variants are obsolete.
  4. Ensure the destination is not noindex and is not blocked from Googlebot crawling.
  5. Include the preferred URL in the XML sitemap and use it for contextual internal links.
  6. Verify the article has a useful title, one meaningful H1 and genuinely helpful content.
  7. Use Search Console URL Inspection to check the Google-selected canonical after Google recrawls.

Practice exercise: create two local HTML pages, one clean guide and one copy with a tracking parameter. Give both the clean absolute canonical URL, then change one canonical to a non-existent URL. Explain which check fails and why a canonical tag alone cannot fix a broken destination.

Official documentation

The examples and recommendations above follow Google Search Central: How to specify a canonical URL and Google: Fix canonicalization issues. These documents explain signals, relative URL pitfalls, sitemap consistency, and why Google's selected URL can differ from a declared preference.
